# Deploying SoulConnect on cPanel / DirectAdmin

This is a single Node.js app — Express serves both the JSON API and the
pre-built React SPA. No external database, no Redis, no S3, no third-party
email service. Everything lives in this folder.

## One-time setup

1. **Upload this `cpanel-app/` folder** to your hosting account (File
   Manager → upload zip → Extract, or use Git Version Control in cPanel).
   Put it somewhere like `/home/youruser/soulconnect`.

2. **cPanel → Setup Node.js App → Create Application**
   - Node.js version: 18 or 20
   - Application mode: Production
   - Application root: `soulconnect` (the folder you just uploaded)
   - Application URL: your domain or subdomain
   - Application startup file: `app.js`

3. **Environment variables** (same page, "Environment variables" section).
   Copy from `.env.example`. At minimum set:
   - `JWT_SECRET` — long random string
   - `ADMIN_BOOTSTRAP_EMAIL` / `ADMIN_BOOTSTRAP_PASSWORD` — your first counselor login
   - `PUBLIC_BASE_URL` — `https://your-domain.com`
   - `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`,
     `SMTP_FROM` — from your cPanel Email Accounts page

4. **Click "Run NPM Install"** in the Node.js App panel.

5. **Build the frontend.** In the same panel use "Run JS Script" and run
   `build`. (Or SSH in and run `npm run build` from the app folder.) This
   produces `client/dist/`.

6. **Restart the app.** First boot will:
   - create `data/app.sqlite`
   - run migrations
   - seed the bootstrap counselor account from your env vars

7. Visit your domain. Sign in to the admin at `/admin/login`.

## Updating later

Upload changed files → if `package.json` changed click **Run NPM Install** →
run `npm run build` → **Restart**.

## Where things live

- `data/app.sqlite` — your database. Back this up.
- `uploads/` — user-attached files.
- `client/dist/` — built SPA, regenerated by `npm run build`.

## Notes

- Chat uses 3-second HTTP polling. Passenger's WebSocket support on shared
  hosting is unreliable; polling is intentional.
- Anonymous submissions never store IP or user-agent. Verified in
  `server/routes/questions.js`.
- A question is **never** public until a counselor edits the sanitized
  `public_title` / `public_content` fields and toggles `is_public`.
