# Deploying GraceLine Answers on cPanel / DirectAdmin

This is a **single Node.js app** — Express serves both the JSON API and the pre-built
React SPA (built with Vite). There is **no external database, no Redis, no S3, and no
third-party email service**. Everything lives in this folder, so it runs on any shared
hosting that offers "Setup Node.js App" (Phusion Passenger).

## One-time setup

1. **Upload this `cpanel-app/` folder** to your hosting account (File Manager → upload
   zip → Extract, or use Git Version Control in cPanel). Put it somewhere like
   `/home/youruser/graceline-answers`.

2. **cPanel → Setup Node.js App → Create Application**
   - Node.js version: **20 or 22** (18+ works if `better-sqlite3` builds; 22.5+ lets the
     app fall back to Node's built-in `node:sqlite` for zero native compilation).
   - Application mode: Production
   - Application root: `graceline-answers` (the folder you just uploaded)
   - Application URL: your domain or subdomain
   - Application startup file: `app.js`

3. **Environment variables** (same page, "Environment variables" section). Copy from
   `.env.example`. At minimum set:
   - `JWT_SECRET` — a strong, unique string of at least 32 characters. The app **refuses
     to start in production** with a missing/weak value.
   - `ADMIN_BOOTSTRAP_EMAIL` / `ADMIN_BOOTSTRAP_PASSWORD` — your first counselor login.
   - `PUBLIC_BASE_URL` — `https://your-domain.com` (no trailing slash). Used in email
     links, the sitemap, RSS, and canonical URLs.
   - `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` —
     from your cPanel Email Accounts page.

4. **Click "Run NPM Install"** in the Node.js App panel.

5. **Build the frontend.** In the same panel use "Run JS Script" and run `build`. (Or
   SSH in and run `npm run build` from the app folder.) This produces `client/dist/`.

6. **Restart the app.** First boot will create `data/app.sqlite`, run migrations, and
   seed the bootstrap counselor account from your env vars.

7. Visit your domain. Sign in to the admin at `/admin/login`.

## Updating later

Upload changed files → if `package.json` changed click **Run NPM Install** → run
`npm run build` → **Restart**.

## Where things live

- `data/app.sqlite` — your database (SQLite). **Back this up.** It's the entire store of
  questions, messages, notes, prayer requests, and accounts.
- `client/dist/` — built SPA, regenerated by `npm run build`.
- `uploads/` — reserved for user attachments (not yet used).

## Database driver

The app prefers `better-sqlite3` (fast, synchronous, recommended on cPanel, where native
modules build cleanly). If `better-sqlite3` cannot be built — e.g. in CI or on a host
without a compiler — the app automatically falls back to Node's built-in `node:sqlite`
(Node 22.5+). You can override the DB location with `DB_PATH` (defaults to
`data/app.sqlite`); use `:memory:` for tests only.

## API endpoints

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/health` | Liveness check |
| POST | `/api/questions` | Submit a question (anonymous or with email) |
| GET | `/api/questions/by-token/:token` | Fetch a seeker's private thread |
| POST | `/api/messages/seeker` | Seeker follow-up message |
| POST | `/api/messages/counselor` | Counselor reply (auth) |
| GET | `/api/messages/poll?token=...&since=...` | Poll for new messages |
| GET | `/api/archive` | List / search published answers |
| GET | `/api/archive/:id` | Single published answer |
| GET | `/api/archive/categories` | Allowed categories |
| POST | `/api/admin/login` · `/logout` · `/me` | Counselor session |
| GET/POST | `/api/admin/questions` | Inbox list / thread |
| POST | `/api/admin/questions/:id/note` / `status` / `publish` | Counseling actions |
| GET | `/api/admin/stats` | Dashboard counts |
| GET/POST | `/api/admin/team` | Team management (admin only) |
| GET/POST | `/api/prayer` | Prayer wall (list / submit) |
| POST | `/api/prayer/:id/pray` | "I prayed" counter |

## SEO endpoints

- `GET /robots.txt` — allows public content, blocks `/admin` and `/api/`.
- `GET /sitemap.xml` — public pages plus every published answer.
- `GET /feed.xml` — RSS feed of published answers.

The SPA fallback also injects route-specific `<title>`, description, canonical, Open
Graph, Twitter, and JSON-LD (Organization / QAPage / BreadcrumbList) for public pages, so
crawlers get correct signals without executing JavaScript.

## Notes

- Chat uses 3-second HTTP polling. Passenger's WebSocket support on shared hosting is
  unreliable; polling is intentional and robust.
- Anonymous submissions never store an IP or user-agent. Verified in
  `server/routes/questions.js`.
- A question is **never** public until a counselor edits the sanitized `public_title` /
  `public_content` / `public_answer` fields and toggles `is_public`.
- Crisis keywords are detected on submit and displayed as a hotline banner on the Ask and
  Thread pages.
- Rate limits are applied to login, submission, messaging, and prayer endpoints.
