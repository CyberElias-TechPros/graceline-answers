# 0001 — Two deployed units with a same-origin API proxy

**Status:** Accepted

## Context
The product is a public, SEO-critical marketing/archive site plus a private, stateful API.
The directive pins the frontend to Vercel and the API to Cloudflare Workers/D1. Calling the
Worker cross-origin from the browser would require CORS and would force `SameSite=None`
cookies, weakening the session model.

## Decision
Deploy the frontend (Vercel) and the Worker (Cloudflare) separately. The Vercel server entry
proxies `/api/*`, `/robots.txt`, `/sitemap.xml` and `/feed.xml` to the Worker using
`API_ORIGIN`, so the browser sees a single origin.

## Consequences
- First-party cookies (`SameSite=Lax`) and the double-submit CSRF check work with no CORS.
- The Worker origin is an environment variable, so previews and production can differ.
- Sitemap/canonical URLs are generated by the Worker from `PUBLIC_SITE_URL`, the single source
  of truth for the canonical origin.
- Long-polls through the Vercel proxy are capped at the proxy's function timeout, so clients
  keep a short stream timeout and fall back to polling.
